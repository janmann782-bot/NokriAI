# Архитектура v0.2

Один процесс asyncio получает Telegram long-polling updates. Роли проверяются по числовому user ID. Владелец 7787565361 уже задан в config/deployment.json, OWNER_ID может явно переопределить его извне. Из Telegram изменить ID владельца нельзя. Группы игнорируются.

Обработка: права/дедупликация → предварительный локальный фильтр → публичные approved источники с event_date/public_from → история и нужная языковая грамматика → атомарный денежный резерв → AnyModel → сверка usage по снимку тарифов → проверка JSON decision → сохранение ответа → анимация Telegram. Локальные фильтры без вызова API записываются как нулевая стоимость и не требуют свободного бюджета.

Один денежный баланс на пользователя для всех моделей. Два скользящих окна 3/24 часа. Никаких квот по числу сообщений. money = ceil((input_tokens * input_usd_per_million + output_tokens * output_usd_per_million) * 1000) в целых nanoUSD. Округление производится 1 раз на весь вызов, учет не зависит от float. requests.cost REAL оставлен только для совместимости/показа, решение о допуске использует spending.amount_nusd/reserved_nusd INTEGER.

Перед отправкой вызова BEGIN IMMEDIATE проверяет совокупность списаний всех моделей и незавершенных резервов. Оценка входа - длина JSON контекста в UTF-8 байтах + 32 единицы на сообщение + 2048 запаса. Выход резервируется до max_output_tokens (по умолчанию 4096, настраиваемый диапазон 128..8192). Снимок входного/выходного тарифа сохраняется в spending, поэтому смена цены во время вызова не меняет учет этого запроса. Свежая конфигурация модели повторно сверяется при резервировании, чтобы не вызвать API по устаревшему соответствию.

Ledger states: held (вызов зарезервирован), settled (известная стоимость), unknown (неполный учет/таймаут), unpriced (старый запрос без известной цены). pending/unknown резервы считаются в обоих бюджетах независимо от срока и даты сброса, пока не получат стоимость при сверке. unpriced старые записи блокируют платные вызовы ограниченного пользователя до /settle. Владелец и активный безлимит обходят ограничения сумм, но не проверку известного тарифа и не учет.

HTTP 401/402/404/429 и другие явные отказы 4xx освобождают резерв, 408/5xx/транспортный сбой сохраняют его как неизвестное списание. Непустой API usage сохраняется даже при пустом ответе, расход учитывается. Наличие обоих конечных целых неотрицательных token counts обязательно для вычисления цены. При отсутствии корректного usage резерв сохраняется. /settle доступен только владельцу. Активный held нельзя вручную обнулить до окончания запроса или восстановления после перезапуска. Известную settled стоимость нельзя переписать этой командой.

Резервирование защищает локальный бюджет от параллельного обхода, но не является гарантией списаний внешнего кошелька: AnyModel может добавить скрытые токены или превысить заявленный предел. Известное превышение резерва записывается целиком и ограничивает последующие вызовы. Абсолютный предел расходов на стороне провайдера не заявлен.

SQL-параметры используются для данных. Динамическое имя поля в административной команде выбирается из фиксированного словаря. API URL/провайдер/семейство модели проходят allowlist. Только AnyModel и ds/deepseek-, qwen/qwen, glm/glm-. Kimi и free-router запрещены. Fallback на другую модель отсутствует.

Lock на пользователя запрещает наложение 2 генераций. Semaphore ограничивает 12 одновременных вызовов. Пакет Telegram до 20 обновлений. Webhook отключается при запуске. Durable offset записывается после обработки пакета. Уникальный requests.update_id предотвращает повторную оплату API после переигрывания пакета. Команды не имеют отдельной дедупликации и могут повториться при аварии до сохранения offset.

После аварии requests.pending становится interrupted. Денежный резерв остается в SQLite. Автоматического повторного платного вызова нет. Сброс бюджета сохраняет полный журнал расходов и все неизвестные резервы. Данные пользователя, память, роли, ключи и доступ к моделям сохраняются при миграции v0.1.

Схема: users, models, settings, secrets, limits (старые h3/day не используются, остался доступ allowed), budgets, spending, requests, api_usage, messages, knowledge, knowledge_fts, objects, audit. Денежные таблицы добавляются при инициализации, старые известные cost мигрируют, неизвестные требуют сверки. Цены и персональные бюджеты задаются из Telegram.

API-ключ шифруется Fernet ключом MASTER_KEY из окружения. Один AnyModel-ключ глобален, ротация owner-only в private chat. Ключ не попадает в историю и журнал. История диалогов и административный аудит лежат в SQLite без отдельного шифрования.

Политический смысловой decision получается из того же платного вызова, а regex выполняет быстрые явные отказы. Это не независимый классификатор. Отключение политического фильтра не открывает секретные/будущие источники. Источники фильтруются до передачи, но абсолютного удаления исходных знаний модели о Земле или полной защиты от prompt injection нет.

Docker Compose подготовлен без публичных портов. Живые API и Docker не запускались в этой среде. Локальные проверки используют unittest, SQLite и HTTPX MockTransport. Установка актуальных ключей и проверка фактического списания по кошельку остаются этапом развертывания.

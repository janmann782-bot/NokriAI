# Nokri AI

Telegram-бот государственного ИИ САР Кефирстан. Python 3.11+, HTTPX, SQLite WAL/FTS5, Fernet. Все языковые модели вызываются **через AnyModel**. Прямые API и Kimi исключены валидатором. Бот работает в личных чатах.

## Состояние поставки

Рабочий исходный код, тесты с подставным HTTP-сервером, импортированный текстовый архив и готовые языковые справочники. Реального подключения к Telegram и платных вызовов AnyModel в этой сборке не было: отсутствуют токен бота и актуальный ключ. Владелец уже прописан: `7787565361` в `config/deployment.json` и `.env.example`. Все модели выключены до настройки владельцем.

Ограничения, которые нельзя скрыть:

- Полный архив не размечен автором по event_date/public_from/access. Поэтому сырой корпус помещен в карантин. Он доступен администраторам через `/kb` и `/inspect`, но не отправляется модели. Публичная база содержит словари и небольшой проверенный набор фактов. Выпуск фрагментов - `/review`. Это не полное знание всего лора на дату 2061 года
- Изображения, PSD, NPZ, скрипты и вложенные ZIP не становятся текстовыми знаниями автоматически. По ним есть опись. Главная политическая карта просмотрена при проверке телефонных зон
- Сильмир и новосильмир подключены через словари/грамматику, без обучения весов модели. Качество перевода нужно проверить на реальных моделях. Вызов `/language silmir` не гарантирует безошибочную речь
- Сервер строго отбирает источники по датам и доступу. Поведение базовой модели, ее исходные знания и смысловые отказы дополнительно зависят от инструкций. Абсолютного «забывания Земли» или защиты от всех промпт-инъекций нет
- Расходы - расчет из usage, возвращенного AnyModel, а не подтвержденная выписка баланса. Полный usage и reported model хранятся отдельно для диагностики

## Быстрый запуск Docker

1. Создайте бота в BotFather. Скопируйте `.env.example` в `.env`
2. Заполните `TELEGRAM_BOT_TOKEN`. `OWNER_ID=7787565361` уже задан в образце. Если OWNER_ID отсутствует или пуст, используется подтвержденный ID из `config/deployment.json`. Переменная окружения может явно переопределить его при переносе проекта
3. Сгенерируйте MASTER_KEY и запишите в `.env`:

```bash
python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

Если локально нет cryptography, после сборки:

```bash
docker compose build
docker compose run --rm --no-deps bot python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
```

4. Ограничьте доступ к `.env`, запустите:

```bash
chmod 600 .env
docker compose up -d --build
docker compose logs --tail 50 bot
```

Первый запуск образа создает SQLite в постоянном Docker volume и загружает публичный корпус из `data/curated.jsonl.gz`. Большая карантинная копия `state/seed.sqlite` не хранится в GitHub (310 МБ, превышает лимит GitHub на файл). Если нужна полная локальная карантинная база из архива поставки, импортируйте ее отдельно через `nokri import`. Повторный запуск сохраняет пользователей, ключи, историю, лимиты, знания и административные изменения. Не запускайте два экземпляра long polling с одним токеном.

5. Откройте личку бота со своего аккаунта. `/myid` позволяет проверить ID после запуска. `/admin` открывает панель
6. `/key` → отправьте общий ключ AnyModel следующим сообщением. Доступно только владельцу, окно 120 секунд. Ключ не идет модели, не пишется в историю, сообщение удаляется по возможности. Telegram все равно обрабатывает ввод ключа, поэтому для отказа от передачи через чат используйте ANYMODEL_API_KEY в окружении при первом запуске
7. `/catalog` проверяет доступные API-ID вашим ключом. `/enable etajd 1`, `/enable joz 1`, `/enable mudris 1` включают найденные соответствия. Включение допустимо только после свежего `/catalog`
8. Для Flash сначала решите вопрос соответствия, см. `docs/MODELS.md`. Быстрая смена ID: `/map flash ТОЧНЫЙ_API_ID`. `/setmodel flash JSON` сохраняет новый JSON, затем `/enable flash 1` явно утверждает замену

Новый ключ заменяет общий ключ для всех будущих запросов сразу. Уже отправленный API-запрос завершится со старым. Ключ можно сменить тем же способом. Бот никогда не показывает сохраненный ключ.

## Запуск без Docker

```bash
python3 -m venv .venv
.venv/bin/pip install .
cp .env.example .env
# заполните .env
mkdir -p state
./.venv/bin/python -m nokri.cli init
./scripts/run.sh
```

Все команды запускаются из корня проекта. Для сервера используйте Docker Compose или собственный systemd unit. SQLite подходит для одного экземпляра бота на небольшом/среднем проекте. Для нескольких процессов потребуется общая очередь, PostgreSQL и распределенные блокировки.

В системном промпте восточно-аурельский язык и русский считаются одним языком. В интерфейсе команда `/language ru` сохранена для совместимости.

## Команды пользователя

| Команда | Действие |
|---|---|
| `/model` | Кнопки выбора модели |
| `/model etajd` | Выбрать модель по логическому ID |
| `/limits` / `/mybudget` | Общий денежный бюджет, расход и резерв всех моделей |
| `/language ru` | Русский |
| `/language silmir` | Сильмир |
| `/language novosilmir` | Новосильмир |
| `/new` | Удалить историю текущего пользователя |
| `/myid` | Числовой ID |
| `/animation on` / `/animation off` | Плавное появление ответа |

История общая между моделями, до 16 последних сообщений на запрос. Полная история хранится в SQLite до `/new`. При смене модели reasoning_content предыдущей модели не переносится, видимый контекст сохраняется.

Во время API-запроса индикатор «печатает…» обновляется каждые 4 секунды. После смысловой проверки ответ появляется порциями с курсором ▍. Это анимация готового проверенного текста через editMessageText, а не выдача необработанного JSON/токенов модели. У длинных ответов анимируется первая часть, остальные приходят сразу. Сбой редактирования приводит к отправке полного текста. Анимация включена по умолчанию и не вызывает дополнительных запросов модели.

## Общий денежный бюджет

Никаких лимитов по числу сообщений. Каждый пользователь имеет **один бюджет на все модели**. Стоимость зависит от входных токенов (включая историю и найденные знания), выходных токенов и тарифа выбранной модели. Переключение модели не обновляет бюджет.

Начальные настройки продукта, которые владелец может сразу поменять:

| Окно | Общий бюджет на пользователя |
|---|---:|
| Скользящие 3 часа | $0.01 |
| Скользящие 24 часа | $0.03 |

Это настройки приложения, не утвержденный лор. Начальное значение в `config/budgets.json`. После создания базы изменения через Telegram сохраняются в SQLite и имеют приоритет над файлом. Денежный учет ведется в USD. Внутри используются целые nanoUSD (1 USD = 1 000 000 000 единиц), поэтому дешевые запросы не округляются до центов и ошибки float не накапливаются.

Например, при тарифах 0.03 USD за 1M входных/выходных токенов ответ с 1 000 входных и 500 выходных стоит $0.000045. Сумма вычитается из обоих общих окон независимо от имени Nokri. Это арифметический пример, не обещание расхода конкретного ответа.

Перед платным вызовом бот атомарно резервирует расчетный максимум: консервативная оценка входа + max_output_tokens. После ответа резерв заменяется расчетом по фактическому usage API и **сохраненным на момент запроса тарифам**. Если свободного бюджета не хватает на резерв, вызов не отправляется. Старая история может сделать резерв заметно больше реального списания. `/new` уменьшает будущий контекст, но не сбрасывает уже потраченный бюджет.

Команды, анимация и локальный отказ фильтра без вызова API бесплатны. Смысловой отказ, сгенерированный API, оплачивается как обычный ответ. Явный отказ API (например 401/402/404/429) освобождает резерв. Таймаут, 5xx, отсутствие usage или аварийное завершение не объявляются бесплатными: резерв остается до сверки. Платный пустой/невалидный ответ учитывается по usage, если он доступен.

Ключевые команды:

```text
# По умолчанию для каждого пользователя, все модели вместе (только владелец)
/budget_default 0.01 0.03
# Индивидуальные суммы USD на 3/24 часа
/budget 123456789 0.05 0.15
# Вернуть пользователя на текущий общий бюджет по умолчанию
/budget 123456789 default
# Тариф модели: USD за 1M input/output токенов (только владелец)
/price etajd 0.03 0.03
# Текущий расход и резерв
/limits
# Общий сброс использованного бюджета пользователя
/reset 123456789
# Доступ, временный/постоянный безлимит
/access 123456789 mudris 0
/unlimited 123456789 24
/unlimited 123456789 forever
/unlimited 123456789 off
/filter 123456789 0
/ban 123456789 1
/adminrole 123456789 1
/global maintenance true
/global timezone Europe/Moscow
/usage
```

`/limit ID USD_3H USD_24H` сохранен как синоним `/budget`, старый синтаксис с именем модели не действует. Можно использовать точку или запятую в суммах. Владелец `7787565361` имеет полный доступ и безлимит. Безлимит снимает ограничение бюджета, но расходы все равно записываются. Даже для владельца модель с неизвестным тарифом требует `/price`, чтобы учет не превращался в фиктивный 0.

Сброс бюджета не удаляет историю расходов и не освобождает pending/unknown резервы. Перезапуск и истечение скользящего окна тоже не снимают неизвестные резервы. После сверки они переходят в обычные расходы, учитываемые по времени начала запроса.

Неизвестные расходы проверяются владельцем:

```text
/unsettled
# После сверки списания в AnyModel: ID запроса из /unsettled и точная сумма USD
/settle 42 0.00015
# Если подтверждено, что списания не было:
/settle 43 0
```

Сверить активный выполняющийся запрос нельзя. После перезапуска он помечается interrupted и может быть сверен владельцем. Назначение личного бюджета, безлимита и сброс доступны администраторам для обычных пользователей. Изменение общего бюджета по умолчанию, тарифов и сверка расходов - только владельцу. Другие администраторы не меняют владельца. Владелец может отключить собственный политический фильтр через `/filter 7787565361 0`.

**Граница точности:** это локальный бюджет по настроенным тарифам и данным AnyModel, не жесткий лимит кошелька провайдера. Резерв - оценка. Если шлюз добавит скрытые токены, превысит max_tokens или изменит тариф, фактический расход может превысить резерв. Бот запишет весь известный расход, покажет превышение и остановит последующие платные запросы исчерпавшего бюджет пользователя. Независимой гарантии фактического списания по кошельку AnyModel нет.

## Обновление с v0.1

Сохраните `.env`, MASTER_KEY и рабочий Docker volume/SQLite. Замените код и пересоберите образ, не копируйте seed.sqlite поверх рабочей базы. `initialize` добавляет денежные таблицы без удаления истории, пользователей, ключей и знаний. Старые ограничения h3/day по моделям больше не применяются. Сохранены ограничения доступа к моделям. Индивидуальные старые квоты не переводятся в деньги произвольно: все пользователи получают общий бюджет по умолчанию, пока администратор не назначит личный.

Старые известные расходы мигрируют в денежный журнал. Запросы с неизвестной стоимостью помечаются unpriced и требуют `/unsettled` → `/settle`, прежде чем пользователь с ограниченным бюджетом продолжит платные диалоги. Неизвестные старые списания не обнуляются автоматически. Старые временные точки сброса покомпонентных квот не переносятся.

## Знания, даты и канон

`data/archive_manifest.json` - все файлы и результат извлечения. `state/seed.sqlite` (только в исходном архиве, не в GitHub) - карантин полного текстового корпуса + публичные словари и проверенные факты. `data/curated.jsonl.gz` - воспроизводимый публичный набор. Два языка не смешиваются.

```text
/kb Крутояр
/inspect ID_ИЗ_ПОИСКА
/review ID_ИЗ_ПОИСКА 2059-03-06 2059-03-06 public approved
```

Проверяйте **весь фрагмент**, а не одну найденную строку. `event_date` - самая поздняя дата события/состояния во фрагменте. `public_from` - когда весь фрагмент мог стать публичным. Для события с известным только годом используйте консервативно 31 декабря. Нельзя ставить 1 января всем документам. Секретные сведения остаются `secret`, неопределенные - `restricted draft`. Администратор может просматривать их, но обычный ответ Nokri никогда их не получает, даже при отключении политического фильтра.

Для новой версии исходников:

```bash
nokri import /path/to/extracted/archive
nokri load /path/to/reviewed.jsonl
```

Импорт не запускает скрипты из архива и ничего не утверждает автоматически. Точные конфликтующие версии не усредняются. В пакет включены исходные текстовые материалы как строки карантинной БД. Для карт и бинарных исходников сохраните оригинальный ZIP отдельно.

Дата берется в Europe/Moscow и получает +35 к году. Для 29 февраля сохраняется день/месяц даже в негригорианском аурельском году, например `2028-02-29 → 2063-02-29`. Это техническая конвенция бота, а не новая астрономия канона. Сервер использует гражданские даты-строки и не пытается создать Gregorian datetime 29 февраля 2063.

Новые бытовые объекты хранятся отдельно в `objects` со статусом generated. Они не становятся каноном. Создание включается по явной просьбе придумать магазин/сервис/фирму. Последние 30 примеров передаются в контекст всех диалогов, обеспечивая повторное использование. Для большого реестра потребуется дополнительный поиск. Владелец видит `/objects` и может удалять `/object_delete ID`.

## Безопасность и эксплуатация

MASTER_KEY хранится отдельно от SQLite. Потеря ключа лишает возможности расшифровать API-ключ. Для резервной копии SQLite используйте online backup:

```bash
nokri backup /secure/path/nokri.sqlite
nokri doctor
python -m unittest discover -s tests -v
```

В Docker: `docker compose exec bot nokri doctor`. Для резервной копии создайте ее в `/app/state`, затем скопируйте `docker compose cp bot:/app/state/backup.sqlite ./backup.sqlite`.

`.env`, текущую рабочую БД и ее backups не публиковать. История диалогов и административный аудит находятся в SQLite без отдельного шифрования. Журнал stdout содержит только коды ошибок и ID, без ключей, URL токена Telegram или тел запросов. Публичного HTTP-сервера и открытых портов нет.

Сетевые назначения при запуске: `api.telegram.org:443`, `anymodel.org:443`. Установка зависимостей и Docker-образа отдельно требуют доступа к PyPI/Docker Hub. Исходящий веб-поиск модели не подключен.
